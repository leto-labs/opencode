## Overview

Tauri v2 introduced official mobile support, allowing the same Rust + WebView architecture to work on iOS and Android. The existing OpenCode desktop codebase already has mobile-ready infrastructure:

```rust
// packages/desktop/src-tauri/src/lib.rs
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    // Tauri setup code
}
```

## Tauri Mobile Architecture

### iOS

- **WebView**: WKWebView (same as desktop macOS)
- **Native Layer**: Swift/Objective-C bridge via Tauri
- **Build System**: Xcode project generated by Tauri

### Android

- **WebView**: Android WebView (Chromium-based)
- **Native Layer**: Kotlin/Java bridge via Tauri
- **Build System**: Gradle project generated by Tauri

## Project Structure

> This repo does not have a separate `packages/mobile/` package. Mobile builds are produced from `packages/desktop/` (Tauri v2).

```
packages/desktop/
├── src/                          # Frontend entry point (desktop + mobile WebView)
├── vite.config.ts
└── src-tauri/
    ├── src/                      # Rust backend + Tauri commands
    ├── Cargo.toml
    ├── build.rs
    ├── tauri.conf.json           # Dev config
    ├── tauri.prod.conf.json      # Prod config
    ├── capabilities/
    │   └── default.json
    ├── plugins/
    │   └── foreground-service/   # Android foreground service plugin (mobile only)
    └── gen/
        ├── android/              # Generated Android project (Gradle)
        └── apple/                # Generated iOS project (Xcode)
```

## Plugin Compatibility

| Plugin                         | Desktop | Mobile  | Notes                        |
| ------------------------------ | ------- | ------- | ---------------------------- |
| `tauri-plugin-http`            | Yes     | Yes     | Full support                 |
| `tauri-plugin-notification`    | Yes     | Yes     | Push notifications on mobile |
| `tauri-plugin-store`           | Yes     | Yes     | Uses Keychain/Keystore       |
| `tauri-plugin-shell`           | Yes     | No      | No shell on mobile           |
| `tauri-plugin-dialog`          | Yes     | Partial | File picker works            |
| `tauri-plugin-updater`         | Yes     | No      | Use App Store/Play Store     |
| `tauri-plugin-window-state`    | Yes     | No      | Not applicable               |
| `tauri-plugin-single-instance` | Yes     | Partial | OS handles this              |

## Platform Implementation

Mobile does not spawn a local sidecar server; it connects to a remote OpenCode server.

- Build-time configuration (Android): see [`ANDROID_BUILD.md`](./ANDROID_BUILD.md) (`OPENCODE_SERVER_URL`, `OPENCODE_SERVER_PASSWORD`, etc.)
- Dev-time defaults: `TAURI_DEV_HOST` (physical device) or `10.0.2.2` (Android emulator), see [`MOBILE_SETUP.md`](../MOBILE_SETUP.md)

## Build Commands

### Development

```bash
# iOS Simulator
cd packages/desktop
bun run tauri ios dev

# Android Emulator
cd packages/desktop
bun run tauri android dev

# Specific iOS device
cd packages/desktop
bun run tauri ios dev --device "iPhone 15 Pro"
```

### Production Build

```bash
# iOS (requires signing)
cd packages/desktop
bun run tauri ios build --release

# Android (requires signing)
cd packages/desktop
bun run tauri android build --release
```

## iOS-Specific Setup

### 1. Initialize iOS Project

```bash
cd packages/desktop
bun run tauri ios init
```

This generates `src-tauri/gen/apple/` with:

- Xcode project files
- Swift bridging code
- Info.plist template

### 2. Configure Capabilities

Edit `src-tauri/gen/apple/[AppName]/Info.plist`:

```xml
<!-- Background audio -->
<key>UIBackgroundModes</key>
<array>
    <string>audio</string>
    <string>voip</string>
</array>

<!-- Microphone access -->
<key>NSMicrophoneUsageDescription</key>
<string>OpenCode needs microphone access for voice input</string>

<!-- Speech recognition (optional) -->
<key>NSSpeechRecognitionUsageDescription</key>
<string>OpenCode uses speech recognition for voice commands</string>
```

### 3. Signing

Configure in Xcode or via `tauri.conf.json`:

- Development Team ID
- Bundle Identifier
- Provisioning Profile

## Android-Specific Setup

### 1. Initialize Android Project

```bash
cd packages/desktop
bun run tauri android init
```

This generates `src-tauri/gen/android/` with:

- Gradle project files
- Kotlin/Java bridging code
- AndroidManifest.xml template

### 2. Configure Permissions

Edit `src-tauri/gen/android/app/src/main/AndroidManifest.xml`:

```xml
<!-- Internet access -->
<uses-permission android:name="android.permission.INTERNET" />

<!-- Microphone for voice -->
<uses-permission android:name="android.permission.RECORD_AUDIO" />

<!-- Foreground service for background audio -->
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_MEDIA_PLAYBACK" />

<!-- Keep screen on during voice session -->
<uses-permission android:name="android.permission.WAKE_LOCK" />
```

### 3. Foreground Service (Background Audio)

For continuous voice interaction, Android requires a foreground service:

```kotlin
// Custom service for background audio
class VoiceService : Service() {
    override fun onStartCommand(intent: Intent?, flags: Int, startId: Int): Int {
        val notification = createNotification()
        startForeground(NOTIFICATION_ID, notification)
        return START_STICKY
    }
}
```

## Known Limitations

1. **No Local Server**: Cannot spawn subprocess sidecar on mobile
2. **WebView Restrictions**: Some Web APIs may be limited
3. **Background Execution**: Strictly limited by OS policies
4. **File System Access**: Sandboxed, limited to app documents
5. **Native Code**: Requires platform-specific implementations for advanced features

## Testing

### Simulators/Emulators

```bash
# List available iOS simulators
xcrun simctl list devices

# List available Android emulators
emulator -list-avds

# Run on specific simulator
bun run tauri ios dev --device "iPhone 15"
bun run tauri android dev --device "Pixel_7_API_34"
```

### Physical Devices

1. **iOS**: Requires Apple Developer account, device must be registered
2. **Android**: Enable USB debugging, connect via ADB
